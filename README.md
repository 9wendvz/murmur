# murmur

A little mood journal for my Mac. Each day I pick a face (faces I drew myself), write a bit, and stick photos, videos, voice memos or doodles on the page. Everything stays on my laptop.

It's written in Swift with SwiftUI and some AppKit, no third-party packages, and it builds with just the Xcode Command Line Tools.

## Download

You need a Mac running macOS 14 (Sonoma) or newer. Apple silicon and Intel both work.

1. Go to the [latest release](../../releases/latest) and download `Diary-1.0.zip`.
2. Double-click the zip to unzip it, then drag **Diary** into your **Applications** folder.
3. Open it. The first time, macOS will say it can't check the app for malicious software. That's because it isn't signed with a paid Apple developer account, not because anything is wrong with it. To open it anyway:
   - Open **System Settings → Privacy & Security**, scroll down to the message about Diary, and click **Open Anyway**. Then confirm.
   - Or, if you're comfortable with Terminal, run:
     ```sh
     xattr -dr com.apple.quarantine /Applications/Diary.app
     ```
   You only have to do this once.
4. Diary asks for the camera, microphone or notifications only when you first use something that needs them.

To update, download the new zip and replace the old app in Applications. Your diary isn't stored inside the app (see [Where the data lives](#where-the-data-lives)), so nothing is lost.

To uninstall, delete the app. If you want your entries gone too, delete `~/Library/Application Support/Diary/`.

### The desktop widget

Choose **Diary → Show Desktop Widget** (⌘⇧D) for a little month calendar on your desktop. Close the main window and the app drops out of the Dock and menu bar, leaving just the widget. Click a day or `[open]` to bring the app back, or right-click the widget to quit. With **Diary → Open at Login** it starts quietly with only the widget.

It's a Diary window, not one of macOS's own widgets, so Diary needs to be running for it to show.

## What it does

- Five mood faces you draw yourself, plus as many extra emotions as you want. Each one gets a name and a color.
- A plain paper page to type on. Photos, videos and drawings sit on the page like stickers: drag them around, resize them from the corner, and the text wraps around them. You can paste images straight in, drag files onto the page, or use the built-in camera.
- Voice memos, recorded in the app.
- A feed view that scrolls through every day like posts, with the calendar following along.
- Search three ways: by meaning (searching "times i felt lonely" finds "spent the evening alone in my room" even though they share no words; more on this below), by exact words, or by date. Dates can be typed almost any way: `11.04`, `nov 4`, `november`, `2026.11`, `yesterday`, `last friday`.
- A mood suggestion based on how your writing sounds, if you haven't picked one yet.
- Insights: a year of moods as a grid of squares, streaks, a chart of picked mood vs. how the writing actually sounds, and the words you use most on each kind of day.
- Important dates (birthdays etc.) with reminders, and a to-do list that understands "essay due friday".
- A small month calendar that sits on the desktop.
- Undo for pretty much everything (⌘Z or ctrl-Z).

## Search

Entries are split into sentences. Each sentence gets turned into a 512-number vector by Apple's on-device sentence embedding model (`NLEmbedding`). A search compares the query against every sentence in one matrix-vector multiply using Accelerate, and each day scores as its best-matching sentence. Exact word matches get a small boost.

The index only re-embeds entries that changed, embeds in parallel across cores, and is saved to disk so the app doesn't rebuild it every launch.

Before settling on this I made a small labeled test set (13 queries over 12 diary-style entries) and compared a few approaches by MRR:

| approach | MRR |
| --- | ---: |
| keyword match | 0.29 |
| sentence embeddings (what the app uses) | 0.55 |

I also tried Apple's newer contextual (BERT-style) embeddings. Used raw, they did worse than keyword search, because every sentence came out with nearly the same vector (similarities all around 0.8). Mean-centering helped a bit but still lost to the sentence model.

Timing, on 10 years of fake daily entries (3,653 entries, 11,764 sentences):

| | |
| --- | ---: |
| one search, start to finish | ~18 ms |
| comparing against all sentences, Accelerate vs a plain loop | 0.43 ms vs 2.24 ms |
| building the index from scratch, 10 cores vs 1 | 19 s vs 54 s |
| loading the saved index on launch | 15 ms |

Full numbers are in [BENCHMARKS.md](BENCHMARKS.md), generated by `./bench.sh`.

## Where the data lives

`~/Library/Application Support/Diary/`. Entries are in `entries.json`, and attachments get copied into `media/`. The app keeps the last 20 copies of the entries in `backups/`, one each time it opens. If the entries file ever fails to load, it sets the file aside and stops saving instead of overwriting it.

Nothing is sent anywhere. The language features (sentiment, keywords, search) all use models that ship with macOS.

## Code

| file | what's in it |
| --- | --- |
| `Store.swift` | entries, attachments, moods, saving/loading, undo |
| `Notebook.swift` | the writing page (an `NSTextView`), stickers on it, paste/drop, the cursor |
| `Stickers.swift` | a draggable, resizable photo/video/drawing on the page |
| `Search.swift`, `SearchView.swift` | the search index and its panel |
| `Insights.swift`, `InsightsView.swift` | sentiment, streaks, keywords, and the insights screen |
| `Faces.swift`, `Drawing.swift` | drawing your own faces, doodles |
| `FeedView.swift` | the scrolling feed |
| `Media.swift`, `Camera.swift` | importing, voice memos, thumbnails, video playback, camera |
| `Dates.swift`, `Todo.swift` | important dates + reminders, to-do list |
| `Views.swift`, `Deck.swift`, `Theme.swift` | main window, the little hardware-style details, colors and font |
| `Widget.swift` | the desktop month widget |

A few things that took some figuring out:

- Older saved files keep loading as the format changes. Missing fields fall back to defaults, and there are tests for files from earlier versions.
- Drawings are stored as strokes with coordinates from 0 to 1 instead of as images, so the same face looks sharp as a 16 px calendar dot or in the 260 px editor.
- Some SwiftUI pieces didn't work here. `VideoPlayer` crashes in apps built without Xcode, so videos use `AVPlayerView`. The system text cursor stretches to the full line height on an empty page and can't be made thinner, so the page draws its own.

## Building it yourself

```sh
xcode-select --install   # the Command Line Tools, if you don't have them
git clone <this repo>
cd diary
./build.sh               # builds Diary.app (open it with: open Diary.app)
./test.sh                # runs the tests
./bench.sh               # runs the benchmarks and rewrites BENCHMARKS.md
```

An app you build yourself doesn't get the security warning.

## Making a release

```sh
./package.sh                                   # universal build → dist/Diary-<version>.zip
gh release create v1.0 dist/Diary-1.0.zip      # or upload the zip on the GitHub releases page
```

The version number comes from `CFBundleShortVersionString` in `build.sh`.
